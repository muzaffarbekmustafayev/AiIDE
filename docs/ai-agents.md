# AI & Agents Integration Guide

The core differentiator of **AiIDE** is its deep, native integration with AI models and autonomous agents. This document details how AI is embedded into the editor, how external models are configured, and the permissions system that keeps autonomous actions safe.

---

## 1. The Bring Your Own Key (BYOK) Model

To maximize flexibility and reduce vendor lock-in, AiIDE operates on a **BYOK (Bring Your Own Key)** architecture. 

### 1.1 OpenRouter & Custom Providers
Users can plug in API keys from aggregators like **OpenRouter**, or directly from providers like OpenAI, Anthropic, or Google.
- **Provider Setup View:** A dedicated modal where users input their keys.
- **Model Selection UI:** A dropdown available directly in the AI Sidebar allowing users to switch models mid-session (e.g., using `claude-3.5-sonnet` for heavy refactoring, and a lighter model like `llama-3` for simple questions).
- **Session Sync:** As described in the architecture, authenticated users will be prompted to pull their securely encrypted API keys from the backend database upon logging in.

### 1.2 Extension System for AI
AiIDE supports **AI Extensions**. 
- Developers can write plugins that inject custom context, specialized prompt wrappers, or local LLM endpoints (like Ollama or LM Studio) into the IDE's ecosystem.
- These extensions can spawn dedicated "Agentic Workspaces" or custom Chat Windows tailored for specific frameworks (e.g., a Next.js specialized agent).

## 2. Modes of Interaction

AI within the IDE operates in two distinct modes:

### 2.1 Conversational Chat Mode
A classic chat interface located in the Right Sidebar.
- **Context Awareness:** The chat automatically knows which file is currently active in the Monaco Editor.
- **`@` Mentions:** Users can type `@` followed by a file or folder name to inject that specific file's content directly into the prompt context.
- **Code Block Actions:** Code generated by the AI in the chat comes with quick-action buttons: 
  - `Copy`
  - `Insert at Cursor`
  - `Replace Current File`

### 2.2 Autonomous Agent Mode
A specialized, task-oriented environment where the AI acts independently based on a high-level goal (e.g., *"Refactor this React component to use Tailwind CSS instead of inline styles"*).

**The Agent Loop:**
1. **Plan Generation:** The AI breaks the goal into discrete steps and displays them to the user.
2. **Tool Execution:** The AI uses predefined backend tools to execute the steps:
   - `readFile(path)`
   - `editFile(path, oldText, newText)`
   - `createFile(path, content)`
   - `runTerminalCommand(command)`
3. **Verification:** The Agent reads the result of its terminal commands (e.g., checking if `npm run build` threw errors) and auto-corrects itself.
4. **Approval Request:** If auto-execute is disabled, the Agent pauses and waits for user approval before modifying files or running commands.

## 3. Permissions & Safety Boundaries

Granting an AI access to a local file system and terminal is inherently risky. AiIDE implements a strict, granular permission matrix.

### Configurable Permission Flags:
In the Settings window, users can toggle the following permissions:
- `allow_file_read`: Can the AI read workspace files without asking? (Default: True)
- `allow_file_creation`: Can the AI create new files/directories? (Default: Ask)
- `allow_file_editing`: Can the AI modify existing code? (Default: Ask)
- `allow_file_deletion`: Can the AI delete files? (Default: False/Ask)
- `allow_terminal_execution`: Can the AI run shell commands? (Default: False)
- `allow_package_installation`: Specific exception for running `npm install` or `pip install`. (Default: Ask)

### The Approval Modal (Agent Feedback View)
When an Agent attempts a restricted action (e.g., editing `src/App.tsx`), a diff view is presented to the user showing exactly what the AI wants to change. The user can:
- **Approve:** The change is written to disk via `/api/fs/file`.
- **Reject:** The action is canceled, and the Agent is informed of the rejection.
- **Modify:** The user manually tweaks the AI's proposed code before saving.

## 4. Context Window Management
To prevent overwhelming the LLM's token limit:
- **Smart Truncation:** Large files are summarized or truncated.
- **Ignore Lists:** Build folders (`node_modules/`, `dist/`, `.git/`) are strictly excluded from AI context searches unless explicitly requested.
- **Token Counting:** A small UI indicator shows approximately how many tokens the current context is consuming before the user hits "Send".
